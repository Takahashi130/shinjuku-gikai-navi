# 区民参加（議案の解説・区民投票）の組み込みと運用

設計は [20261003_1900_区民参加機能の実装計画.md](20261003_1900_区民参加機能の実装計画.md)。この文書は、レビューの指摘を直したあとの「画面への置き方」と「運営の手順」をまとめる。

## 1. 画面への置き方（2026-10-04 に新しいデザインへ組み込み済み）

### 1.1 議案詳細（`BillDetailLayout`）

`web/src/features/bills/server/components/bill-detail/bill-detail-layout.tsx` が、議案ページの差し込み口（`bill-slots.tsx`）に次のように入れている。プレビュー（`/preview/bills/[id]`）は `<BillDetailLayout bill={bill} preview />` で描き、解説の下書きも出す（公開前の議案には投票できない）。

| 差し込み口 | 入れているもの | 中身 |
|---|---|---|
| `BillExplainerSlot` | `BillExplainerSection`（Suspense の中） | 事前解説。7枚のスライド＋「一覧で読む」、出典と根拠のパネル、「AI（Claude）が作成し、別のAIが資料と照合」の表示。無ければ理由（準備中・人事案件・過去の議案など） |
| `CitizenVoteSlot`（「区民の意思 vs 議会の議決」の区民の面） | `CitizenVoteResultPanel` | 区民投票の結果。本人が投票した後か締切後だけ数字を出す。「これまでの票／採決前の票」と「採決後の票」を分け、30票以上・差5ポイント以内は拮抗の判定と、議会の議決とのズレ（分かれた／同じ向き）を出す。割合を大きな数字で出すのは30票以上のときだけ（それまでは横棒と小さな票数）。受付を止めているときは「受付停止中」、公開前の議案は「公開前」とし、「投票受付中」と書かない。締切より後に受付を始めた回（過去の議案。`opens_at >= closes_at`）は、採決前の欄・判定・議会との比較を出さず、「採決のあとに受付を始めたため、採決前の票はありません」と書く |
| `CastVoteSlot`（濃色の帯「あなたの意思を投じる」） | `CastVoteBand` | 賛成・反対、締切までの日数、本人の票と取り消し、「参考値・区民確認なし」の注記。人事案件・受付前・受付終了・受付停止中・公開前は、ボタンを出さずに理由を書く。取り消しは確かめてから行う。締切の前に入れた票を締切のあとに選び直す・取り消すと、その票は採決前の票から外れて戻らないので、帯にそう書き、選び直しも確かめてから行う |
| `BillCommentsSlot` | （準備中のまま） | |

- 結果の面と投票の帯は離れた場所にあるが、どちらも `CitizenVoteProvider`（`citizen-votes/client/components/citizen-vote-provider.tsx`）の中に置き、帯で投票すると結果の面もすぐ変わる。組み立ては `bills/server/components/bill-detail/bill-vote-sections.tsx`（Suspense の中でデータを取り、待つ間も議会の議決の面は先に出す）。
- 投票の帯へのリンクの行き先（id `cast-vote`）は、帯そのものではなく外側の `CastVoteAnchor` に付けている。帯は Suspense の中で読み込むので、読み込み中の骨組みにも同じ id が付き、新しいタブ・再読み込み・共有されたリンクでも帯まで移動する。ほかのページからは `billVoteHref(billId)`（`/bills/<id>#cast-vote`）で送る。
- 投票・取り消しが成功したら、その議案の集計のキャッシュ（タグ `citizen-votes:summary:<議案ID>`）を消す（`server/actions`）。投票の直後に再読み込みしたり、戻るボタンで戻ったりしても、前の数が出ない。
- ふりがな表示（Rubyful）が ON だと、`main` の中の p・span・a などの中身が差し替えられる（`lib/rubyful/selector.ts`）。投票で変わる文字（結果の面・本人の票・スライドの番号）は、key を変えて要素ごと作り直している。テストは `lib/rubyful/simulate-rubyful.ts` で差し替えをまねて、落ちないこと・新しい値が出ることを確かめる。
- `BillParticipationPanel`（解説 → 投票の帯 → 結果を縦に並べた1か所の入口）は、開発用の実データのページ（`/dev/features/participation/live`）だけで使う。

### 1.2 一覧のカード：`getBillParticipationBadges` と `BillCard` の `participation`

- loader（Server）で、一覧に出す議案の ID をまとめて渡す（N+1 にしない）。
  ```ts
  import { getBillParticipationBadges } from "@/features/bill-participation/server/loaders/get-bill-participation-badges";
  const badgesById = await getBillParticipationBadges(bills.map((b) => b.id));
  ```
- `BillCard` に `participation={badgesById[bill.id]}` を渡すと、カードの下に印（`ParticipationBadges`）が出る。印が無ければ何も描かない。
- 印は「投票受付中・あと n 日」「解説あり」「区民 ○○多数（・議会と分かれた）」の順。結果の印は締切の後だけ出る。投票の受付を止めているあいだ（2.4）は「投票受付中」を出さない。
- 取得は 60 秒キャッシュ。失敗しても一覧は止めず、印なし（空のオブジェクト）を返す。
- 置いている場所：トップの「審議中の議案」（`home-page.tsx`）、議案一覧（`bills-list-page.tsx`。表示しているページの分だけ）、会期ごとの議案一覧（`diet-session-bills-page.tsx`）。

### 1.3 トップ

- ヒーローの数字に「区民投票を受付中の議案」（締切前のものだけ。`getOpenCitizenVoteStats`）を足した。受付中がいまの会期だけなら、その会期の議案一覧へ送る。投票の受付を止めているあいだは、このカードを出さない。
- 「区民の意思 vs 議会の議決」の区民の面は `HomeCitizenVotePanel`（`getCitizenVoteSnapshot`）。本人の票を読まないので、結果は締切の後だけ出す。票が無いときや締切前は、受付中であることとその議案の投票の帯へのリンクを出す。受付を止めているときは「受付停止中」とし、リンクを出さない。

### 1.4 組み込んだあとの確認（2026-10-04 に実施）

- web の開発サーバー（`pnpm exec dotenv -e .env -- pnpm --filter web exec next dev --turbopack --port 3200`）で、r8-teirei-3 の第63号議案のページで解説（スライド・一覧・出典のパネル）が出ること、投票 → 結果の表示 → 選び直し → 取り消しが開発用 DB で動くことを確かめた（確かめた票は取り消し、`poll_responses` は 0 件に戻した）。
- 人事案件（r8-teirei-3-doi-1）で、解説が「対象外」、投票の帯にボタンが出ないことを確かめた。
- 375px と 1280px で横にはみ出さないことを確かめた。

## 2. 運営の手順

### 2.1 先議がある会期

会期ページからは、どの議案が先議で採決されるか分からない。そのため取り込み（`ingest`）は、すべての議案の締切を会期の採決予定（`diet_sessions.final_vote_at`）にし、先議（`early_vote_at`）があれば警告を出す。

先議の議案が分かったら、**先議の前に**締切を先議の予定に直す。

```sh
pnpm polls:set-close r9-teirei-1-gian-5 r9-teirei-1-shonin-1 --early --dry-run   # 確認
pnpm polls:set-close r9-teirei-1-gian-5 r9-teirei-1-shonin-1 --early             # 開発用 DB
pnpm polls:set-close r9-teirei-1-gian-5 r9-teirei-1-shonin-1 --early --env prod  # 本番（毎回確認あり）
```

- `--early` は、議案の会期の `early_vote_at` を締切にし、`closes_at_source = 'manual'` にする（取り込みし直しても変わらない）。
- 会期ページの先議の行に時刻が無いときは、同じ日の直前の時刻（多くは 14 時）を `early_vote_at` にしている。実際の採決はそれより後のことがあるが、締切が早い分には「採決後の票を採決前として数える」ことは起きない。

### 2.2 採決の時刻が会期ページに書かれていない会期

取り込みは、直前の行の時刻（無ければ 14 時）を締切にし、「下限の時刻」であることを警告する（例：令和2年第1回臨時会は 15:59）。実際の時刻が分かったら直す。

```sh
pnpm polls:set-close <議案slug>... --at "2026-12-10 16:30"   # 時差を書かなければ日本時間
```

- 締切を過ぎた回の締切は、取り込みでは変えない（変えると過去の票の採決前・後の区分が入れ替わるため）。日程とずれていれば警告だけ出す。
- `polls:set-close` で、採決前・後の区分が入れ替わる票がある回を直すときは `--force` が要る（件数が出る）。

### 2.3 不正が疑われるとき・対象外にしたいとき

```sh
pnpm polls:hide <議案slug>...           # 非表示：集計・結果の表示から外し、新しい票を受け付けない
pnpm polls:hide <議案slug>... --unhide  # 戻す
```

- 非表示にしても票は消さない。投票した人は、議案ページで自分の票を取り消せる。
- 個々の票を見分けて除く手段は作っていない（票と IP を結びつけないため）。利用規約も「その議案の投票の受付と結果の表示を止める」としている。

### 2.4 投票の受付を止める（緊急停止）

- 本番の環境変数 `PARTICIPATION_HASH_SECRET` を外す（または32文字未満にする）と、新しい票を受け付けなくなる（`isCitizenVotingEnabled()` が false）。
- このとき、受付中を示す表示もすべて止まる：議案ページの帯は「現在、投票の受付を停止しています」、結果の面は「受付停止中」（締切と「投票して結果を見る」のリンクを出さない）、トップの「区民投票を受付中の議案」のカードは出さず、比較カードの区民の面も「受付停止中」、一覧のカードの「投票受付中・あと n 日」の印も出さない。
- 取り消しは止まらない（同じ人の回数制限だけをかけて受け付ける）。本人の票があれば、カードに「あなたの票：〜／取り消す」が出る。
- 本番の Vercel に秘密鍵を入れ忘れたまま公開しても、同じ状態になる（5章の確認事項）。

### 2.5 回数制限

| 環境変数 | 既定 | 内容 |
|---|---|---|
| `PARTICIPATION_VOTE_RATE_LIMIT_PER_USER` | 10 / 分 | 同じ匿名 ID の投票・取り消し |
| `PARTICIPATION_VOTE_RATE_LIMIT_PER_IP` | 20 / 分 | 同じ接続元（IPv6 は /64）の投票・取り消し |
| `PARTICIPATION_VOTE_RATE_LIMIT_PER_IP_BILL_HOUR` | 10 / 時 | 同じ接続元から同じ議案への新しい票（選び直し・取り消しは数えない） |

- キーは HMAC（`PARTICIPATION_HASH_SECRET`）を通した値（接続元は用途 `ip`・`ip_bill`、匿名 ID は用途 `user`）。秘密鍵が無いとき（受付停止中の取り消し）だけ、ハッシュにできないので匿名 ID のままキーにする。
- `api_rate_limits` の古い行（1時間より前の窓）は、そのあとに投票・取り消し（または公開 API の利用）で新しい窓の行ができたときにまとめて消える（`increment_api_rate_limit`）。操作が無ければ残る。プライバシーポリシーの「5」もこの書き方。
- 本番の Supabase ダッシュボード（Authentication → Rate Limits）で、匿名サインインの上限（1時間あたり・IP ごと）を確かめる。ローカルの `supabase/config.toml` は 30 / 時。
- 将来ロボット確認（Turnstile）を入れるときは、`consumeVoteRateLimit` の前に検証を挟む。

### 2.6 匿名 ID のログインの記録

- 投票ボタン（AI インタビューではページを開いたとき）で作る匿名ユーザーごとに、Supabase Auth が `auth.sessions` などに接続元の IP とブラウザ情報を保存する。プライバシーポリシーの「1」「5」に書いてある。
- 古い匿名ユーザーやセッションを消す運用（セッションの期限の設定、掃除）は未定。`auth` スキーマを SQL で直接書きかえるのは避け、Supabase の設定か Admin API で行う。

## 3. DB の変更（20261006100000）

`supabase/migrations/20261006100000_cascade_polls_and_hide_recommendation_polls.sql`

- `polls.bill_id` を `on delete cascade` にする（票の無い議案は回ごと削除できる。票がある議案は `poll_responses` の `restrict` で削除が止まる）。
- 議案名に「候補者の推薦」を含む議案の「議決」の回を非表示にする（3件：r1-teirei-2-giin-9、r5-teirei-2-giin-9、r7-teirei-2-giin-7）。
- `count_poll_responses_by_bill_ids` が decision 専用であることをコメントに書く。

型（`supabase.types.ts`）は変わらない。

### 適用方法

開発用 DB には、別ブランチ（議員ページ）のマイグレーション 20261005100000・20261005110000 も当たっているため、`npx supabase db push --include-all` は使わない（このブランチに無い版で止まる・別ブランチの版を巻き込む）。どちらか一方の方法で当てる。

- マージで履歴がそろってから `npx supabase migration list --linked` でずれが無いことを確かめ、`npx supabase db push --linked` で当てる。
- 先に開発用 DB だけに当てるなら、SQL エディタ（または `psql`）でこのファイルの中身を実行し、`npx supabase migration repair --linked --status applied 20261006100000` で履歴に記録する。

本番には、マージ後に同じ手順で当てる。

- `explainers/` は手元の develop にマージ済み。ただし origin/develop には push していない（2026-10-04 時点で手元が5コミット先）。解説の下の「解説の元ファイル（GitHub）」のリンク（`GITHUB_REPO/blob/develop/explainers/...`）は、push するまで 404 になる。公開の前に、ユーザーの確認を取ってから develop を push する（5章）。
