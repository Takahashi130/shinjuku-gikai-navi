# 区民参加（議案の解説・区民投票）の組み込みと運用

設計は [20261003_1900_区民参加機能の実装計画.md](20261003_1900_区民参加機能の実装計画.md)。この文書は、レビューの指摘を直したあとの「画面への置き方」と「運営の手順」をまとめる。

## 1. 画面への置き方（まだ本物の議案ページには置いていない）

`feat/participation` ブランチでは、解説と投票の部品は `/dev/features/participation` でしか使っていない。議案ページのデザインを別ブランチで作り直しているため、組み込みはその作業と順番を決めてから行う（投票の受付を始める 10/12 ごろまでに）。

### 1.1 議案詳細：`BillParticipationPanel`

`web/src/features/bill-participation/server/components/bill-participation-panel.tsx`（Server Component）

| props | 型 | 内容 |
|---|---|---|
| `billId` | `string`（必須） | `bills.id`（UUID） |
| `preview` | `boolean`（省略時 `false`） | トークン付きのプレビュー（`/preview/bills/[id]`）で `true`。解説の下書きも見せる（公開前の議案には投票できない） |
| `className` | `string` | 外側の余白など |

- 中身は「解説（`BillExplainerSection`）→ 区民投票（`CitizenVoteSection`）」の順。それぞれ `Suspense` で包んであり、議案ページのほかの部分を待たせない。データが取れない部分は出さない。
- 置く場所の想定：議案詳細（`web/src/features/bills/server/components/bill-detail/bill-detail-layout.tsx`）の本文（`<BillContent />`）の後、インタビューや共有ボタンより前。
  ```tsx
  <BillParticipationPanel billId={bill.id} />
  ```
- プレビュー（`web/src/app/(main)/preview/bills/[id]/page.tsx` から描く議案詳細）では `preview` を付ける。
  ```tsx
  <BillParticipationPanel billId={bill.id} preview />
  ```
- Client Component の中には置けない（Server Component から描く）。
- 人事案件（同意・諮問と、議案名に「候補者の推薦」を含む議案）では、解説は「対象外」、投票カードは出ない。

### 1.2 一覧のカード：`getBillParticipationBadges` と `ParticipationBadges`

- loader（Server）で、一覧に出す議案の ID をまとめて渡す（N+1 にしない）。
  ```ts
  import { getBillParticipationBadges } from "@/features/bill-participation/server/loaders/get-bill-participation-badges";
  const badgesById = await getBillParticipationBadges(bills.map((b) => b.id));
  // badgesById: Record<billId, ParticipationBadge[]>（Client Component にそのまま渡せる）
  ```
- カード（Server / Client どちらでもよい）で印を出す。印が無ければ何も描かない。
  ```tsx
  import { ParticipationBadges } from "@/features/bill-participation/client/components/participation-badges";
  <ParticipationBadges badges={badgesById[bill.id]} />
  ```
- 印は「解説あり」「投票受付中・あと n 日」「区民 ○○多数（・議会と分かれた）」。結果の印は締切の後だけ出る。
- 取得は 60 秒キャッシュ。失敗しても一覧は止めず、印なし（空のオブジェクト）を返す。
- 置く場所の想定：議案一覧（`bill-list.tsx` の `BillCard`）、ホームの注目の議案、会期ごとの議案一覧のカード。

### 1.3 組み込んだあとの確認

- web の開発サーバー（例：`pnpm --filter web dev -- --port 3300`）で、r8-teirei-3 の議案ページ（例：第63号議案）を開き、解説・投票カード・一覧の印が出ることを確かめる。
- 人事案件（r8-teirei-3-doi-*）で投票カードが出ず、解説が「対象外」になることを確かめる。

## 2. 運営の手順

### 2.1 先議がある会期

会期ページからは、どの議案が先議で採決されるか分からない。そのため取り込み（`ingest`）は、すべての議案の締切を会期の採決予定（`diet_sessions.final_vote_at`）にし、先議（`early_vote_at`）があれば警告を出す。

先議の議案が分かったら、**先議の前に**締切を先議の予定に直す。

```sh
pnpm polls:set-close r9-teirei-1-gian-5 r9-teirei-1-shonin-1 --early --dry-run   # 確認
pnpm polls:set-close r9-teirei-1-gian-5 r9-teirei-1-shonin-1 --early             # 開発用 DB
pnpm polls:set-close r9-teirei-1-gian-5 r9-teirei-1-shonin-1 --early --env prod  # 本番（毎回確認あり）
```

- `--early` は、議案の会期の `early_vote_at` を締切にし、`closes_at_source = 'manual'` にする（取り込みし直しても変わらない）。
- 会期ページの先議の行に時刻が無いときは、同じ日の直前の時刻（多くは 14 時）を `early_vote_at` にしている。実際の採決はそれより後のことがあるが、締切が早い分には「採決後の票を採決前として数える」ことは起きない。

### 2.2 採決の時刻が会期ページに書かれていない会期

取り込みは、直前の行の時刻（無ければ 14 時）を締切にし、「下限の時刻」であることを警告する（例：令和2年第1回臨時会は 15:59）。実際の時刻が分かったら直す。

```sh
pnpm polls:set-close <議案slug>... --at "2026-12-10 16:30"   # 時差を書かなければ日本時間
```

- 締切を過ぎた回の締切は、取り込みでは変えない（変えると過去の票の採決前・後の区分が入れ替わるため）。日程とずれていれば警告だけ出す。
- `polls:set-close` で、採決前・後の区分が入れ替わる票がある回を直すときは `--force` が要る（件数が出る）。

### 2.3 不正が疑われるとき・対象外にしたいとき

```sh
pnpm polls:hide <議案slug>...           # 非表示：集計・結果の表示から外し、新しい票を受け付けない
pnpm polls:hide <議案slug>... --unhide  # 戻す
```

- 非表示にしても票は消さない。投票した人は、議案ページで自分の票を取り消せる。
- 個々の票を見分けて除く手段は作っていない（票と IP を結びつけないため）。利用規約も「その議案の投票の受付と結果の表示を止める」としている。

### 2.4 投票の受付を止める（緊急停止）

- 本番の環境変数 `PARTICIPATION_HASH_SECRET` を外す（または32文字未満にする）と、新しい票を受け付けなくなる。
- 取り消しは止まらない（同じ人の回数制限だけをかけて受け付ける）。本人の票があれば、カードに「あなたの票：〜／取り消す」が出る。

### 2.5 回数制限

| 環境変数 | 既定 | 内容 |
|---|---|---|
| `PARTICIPATION_VOTE_RATE_LIMIT_PER_USER` | 10 / 分 | 同じ匿名 ID の投票・取り消し |
| `PARTICIPATION_VOTE_RATE_LIMIT_PER_IP` | 20 / 分 | 同じ接続元（IPv6 は /64）の投票・取り消し |
| `PARTICIPATION_VOTE_RATE_LIMIT_PER_IP_BILL_HOUR` | 10 / 時 | 同じ接続元から同じ議案への新しい票（選び直し・取り消しは数えない） |

- キーは HMAC（`PARTICIPATION_HASH_SECRET`）を通した値だけ。`api_rate_limits` の行は、通常 2 時間以内に消える。
- 本番の Supabase ダッシュボード（Authentication → Rate Limits）で、匿名サインインの上限（1時間あたり・IP ごと）を確かめる。ローカルの `supabase/config.toml` は 30 / 時。
- 将来ロボット確認（Turnstile）を入れるときは、`consumeVoteRateLimit` の前に検証を挟む。

### 2.6 匿名 ID のログインの記録

- 投票ボタン（AI インタビューではページを開いたとき）で作る匿名ユーザーごとに、Supabase Auth が `auth.sessions` などに接続元の IP とブラウザ情報を保存する。プライバシーポリシーの「1」「5」に書いてある。
- 古い匿名ユーザーやセッションを消す運用（セッションの期限の設定、掃除）は未定。`auth` スキーマを SQL で直接書きかえるのは避け、Supabase の設定か Admin API で行う。

## 3. DB の変更（20261006100000）

`supabase/migrations/20261006100000_cascade_polls_and_hide_recommendation_polls.sql`

- `polls.bill_id` を `on delete cascade` にする（票の無い議案は回ごと削除できる。票がある議案は `poll_responses` の `restrict` で削除が止まる）。
- 議案名に「候補者の推薦」を含む議案の「議決」の回を非表示にする（3件：r1-teirei-2-giin-9、r5-teirei-2-giin-9、r7-teirei-2-giin-7）。
- `count_poll_responses_by_bill_ids` が decision 専用であることをコメントに書く。

型（`supabase.types.ts`）は変わらない。

### 適用方法

開発用 DB には、別ブランチ（議員ページ）のマイグレーション 20261005100000・20261005110000 も当たっているため、`npx supabase db push --include-all` は使わない（このブランチに無い版で止まる・別ブランチの版を巻き込む）。どちらか一方の方法で当てる。

- マージで履歴がそろってから `npx supabase migration list --linked` でずれが無いことを確かめ、`npx supabase db push --linked` で当てる。
- 先に開発用 DB だけに当てるなら、SQL エディタ（または `psql`）でこのファイルの中身を実行し、`npx supabase migration repair --linked --status applied 20261006100000` で履歴に記録する。

本番には、マージ後に同じ手順で当てる。
